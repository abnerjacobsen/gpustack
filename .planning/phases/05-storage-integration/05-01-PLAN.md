## Key Research Insights
From 05-storage-integration-RESEARCH.md:
1. **AZ is REQUIRED**: EBS volumes must be created in the same AZ as the instance
2. **Device naming**: Use /dev/sd[f-p] pattern (e.g., /dev/sdf for idx=0, /dev/sdg for idx=1)
3. **Wait for available state**: Use get_waiter('volume_available') before attachment
4. **Tag at creation**: Use TagSpecifications with Name, ManagedBy, WorkerId, VolumeIndex, Format
5. **Volume type**: Use gp3 for better performance, enable encryption by default
6. **Cleanup on failure**: Delete created volumes if attachment fails

**Step 1: Add helper method _get_instance_az()**
- Get instance AZ from describe_instances API
- Parse response: response['Reservations'][0]['Instances'][0]['Placement']['AvailabilityZone']
- Handle errors (instance not found, no AZ) with RuntimeError
- Use existing _handle_aws_error pattern

**Step 2: Add helper method _create_volume()**
- Generate name: f"gpustack-vol-{worker_id}-{idx}" or volume.name if provided
- Call client.create_volume() with:
  - AvailabilityZone=az (REQUIRED - from _get_instance_az)
  - Size=volume.size_gb
  - VolumeType='gp3' (better performance than gp2)
  - Encrypted=True (security best practice)
  - TagSpecifications with tags: Name, ManagedBy=GPUStack, WorkerId, VolumeIndex, Format
- Wait for volume_available using get_waiter('volume_available')
- Return volume_id from response['VolumeId']
- Handle errors with cleanup (call _delete_volume on failure)

**Step 3: Add helper method _attach_volume()**
- Generate device name from index: /dev/sd[f-p] array (idx 0=/dev/sdf, idx 1=/dev/sdg, etc.)
- Maximum 11 volumes supported (/dev/sdf to /dev/sdp)
- Call client.attach_volume(VolumeId=vol_id, InstanceId=instance_id, Device=device)
- Wait for volume_in_use using get_waiter('volume_in_use')
- Handle errors with cleanup (delete volume on attachment failure)

**Step 4: Add helper method _delete_volume()**
- Call client.delete_volume(VolumeId=volume_id)
- Log warning on failure (don't raise - this is cleanup)
- Wrap in try/except ClientError

**Step 5: Implement main create_volumes_and_attach() method**
- Return [] early if no volumes provided
- Get client using async with self._get_client() as client
- Get instance AZ using _get_instance_az()
- Validate instance is running or stopped (not terminated)
- Loop through volumes with enumerate for index:
  - Validate size_gb > 0, raise ValueError if invalid
  - Validate format in ['ext4', 'xfs'], raise ValueError if invalid
  - Call _create_volume() to create and wait for available state
  - Call _attach_volume() to attach and wait for in-use state
  - Append volume_id to list
- Return list of volume_ids

**Error Handling Requirements:**
- ValueError for invalid volume specs (size_gb <= 0, bad format)
- RuntimeError for instance not found or not in valid state
- EBS-specific error codes (InvalidVolume.ZoneMismatch, AttachmentLimitExceeded, InvalidParameterValue, IncorrectState)
- Cleanup created volumes on any failure during the loop

**Pattern Consistency:**
- Use logger.info() for operations: "Created EBS volume {vol_id} ({size}GB) in {az}"
- Use logger.warning() for cleanup failures
- Follow existing _handle_aws_error pattern for AWS errors
- Use secrets.token_hex(4) for random suffixes (like existing code)
